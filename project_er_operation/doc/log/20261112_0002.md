## 2. 実装の詳細

### 2.1 UX

- **ヘッダのドラッグだけで移動**: 本体の列行を押しても移動しない(選択だけ)。ロック中は従来どおり動かない。
- **「ドラッグ中に何も表示されない」の原因**: キャンバスの Painter が構築時の値(ドラッグ中の位置)を持ち、ドラッグ中は再構築されていなかった。移動の確定(離したとき)まで一切描き直されていなかった。ドラッグ中に再構築するよう直した。
- **ドラッグ中の表示**: ドラッグ開始時の位置に、元のエンティティを半透明で残す(複数選択なら全て)。
- **列のドラッグ**: 列行を押してドラッグすると、元の列行の強調、元からポインタまでの線、ポインタ位置の列の画像(物理名と型)、ドロップ先(列行またはエンティティ)の強調を表示する。離すと `AddRelationshipCommand`(ドラッグ元が親、ドロップ先が子)を実行する。
  - ドロップ先が列行なら、その列を対応する外部キー列に固定する(他の列は 7-5 の規則)。
  - 親の列が主キー/ユニークでない、同じテーブル、ロック中、ビューへのドロップは拒否または何もしない(メッセージはステータスバー)。
  - ドロップ先の指定は「(左)/(右)」の意味が仕様上明示されていないため、**左=ドラッグ元=親、右=ドロップ先=子**と解釈した(「仮定」参照)。
- 位置情報だけのコマンドではないため、`AddRelationshipCommand` の引数(`parentColumnId`、`childColumnId`)は JSON に含め、キャッシュの再生でも同じ結果になる。

## 3. flutter_qjs の評価(実装なし)

### 結論

**flutter_qjs を使い続けることは、長期的には正しくない。`flutter_js` などの更新されているパッケージへの移行を推奨する。** ただし、移行の可否は下記の「事前に検証すべきこと」(特に実行のタイムアウト)の結果次第で、今回は検証も実装もしていない。

### 根拠(2026-11-12 に pub.dev で確認した事実)

| 項目 | flutter_qjs | flutter_js |
|---|---|---|
| 最新版 | 0.3.7(2022-05-19) | 0.8.7(2026-01-27) |
| 直近の更新 | 約4年半前。0.3.x は2021〜2022年のみ | 0.8.2(2025-02)から0.8.7(2026-01)まで6回 |
| Dart SDK 制約 | `>=2.12.0 <3.0.0` | `>=3.0.0 <4.0.0` |
| ffi | `^1.0.0`(古い) | `^2.0.0` |
| 対応(Windows) | あり(ただし本リポジトリでは未修正だとビルドできない) | あり(タグに Windows) |
| 評価 | — | likes 360、pub points 140/160、30日のダウンロード約5.7万、Dart 3 対応のタグ |

- **実害を既に受けている**: flutter_qjs 0.3.7 は Dart 3.13 でコンパイルできず(FFI コールバックの戻り値の null 許容)、`third_party/flutter_qjs` に複製して2行のパッチを当てている。上流の修正は期待できない(4年半更新が無い)。
- **依存の更新を妨げている**: `ffi ^1.0.0` の制約のため、`file_picker` が古い 4.6.1 に固定され、取得のたびに警告が出る。`ffi 2.x` を要求する新しいパッケージは入れられない。
- **ネイティブコードを自前で保守することになる**: パッチ版を保守するか、同梱の QuickJS を更新するかは、いずれも本アプリ側の負担になる。

### 移行の影響範囲(小さい)

- JavaScript の実行は `PostRunner` インターフェースの背後に隔離してあるため(2-6)、変更は `lib/runner/qjs_post_runner.dart`、`pubspec.yaml`、`windows/` のプラグイン、テストの DLL コピー(`test/support/post_support.dart`)に限られる。モデル、生成、UI は影響を受けない。
- 生成用JSON、`postgresql.post`、golden テストはそのまま再利用でき、**移行後の動作確認に使える**。

### 事前に検証すべきこと(未検証)

以下は、パッケージの説明からは確認できていないため、移行する場合は小さな検証(スパイク)で先に確認する。

1. **Windows のビルド**: このツールチェーン(VS BuildTools、CMake)で、ネイティブ部分がビルドでき、DLL が配置される。
2. **実行のタイムアウト(9.6-1-4 の要件)**: 無限ループの JS を中断できるか。flutter_qjs は `IsolateQjs` の `timeout` で中断できている(テスト済み)。flutter_js に同等の機能が無い場合は、実行を別 Isolate に置いて Isolate ごと終了する方式で代替できるか。
3. **別 Isolate での実行**: `evaluate` が同期のため、UIを止めないよう `Isolate.run` などで包む必要がある(2-13)。ネイティブのランタイムを Isolate 内で生成して使えるか。
4. **ES2020**(ポストファイルの契約 9.6-4): 同梱の QuickJS がテンプレートリテラル、`??`、`?.` を扱えるか(現行の golden テストの JS で確認できる)。
5. **`console.log` の回収**と、例外のメッセージ・スタックの取得方法。
6. 既存の `ffi` に起因する依存の固定が解消され、`file_picker` を更新できること。

### 代替案

- `flutter_qjs` を自前のフォークとして維持する(現状の延長。更新コストを負担し続ける)。
- QuickJS を `dart:ffi` で直接使う(自由度は高いが、保守量が最も多い)。
- 移行せず、評価の結果を踏まえて判断を保留する(短期的には現状のパッチで動作している)。

推奨は「flutter_js へ移行する。ただし上の 1〜4 を先に検証する」。

## 5. 付録D以外で新たに仮定を置いた事項

1. 列のドラッグでの「(左)/(右)」は、**左=ドラッグ元=親、右=ドロップ先=子**とした。
2. ドラッグ中の列の画像は、列行そのものではなく、物理名と型を入れた簡易なチップにした。
3. 型管理で使用中の型を削除するとき、置換先の候補は削除する型以外の全ての型。
4. メソッド管理: 名前の重複は大文字小文字を区別しない。OK時に不正があれば、最初の不正なメソッドを選択し直す。
5. 共通列パターン管理: 名前の重複は大文字小文字を区別する(パターン名は物理名ではないため)。列の物理名はパターン内で大文字小文字を区別せず重複不可。
6. 関数ビューの定義ダイアログで新規のとき、物理名の既定は `view_N`(未使用の最小の正の整数)。
7. トリガーの「本体(入力)」は、対象DBを選んで1つずつ編集する(確定は入力欄のフォーカス喪失)。
8. 結合ビューは、サイドメニュー・メニュー・右クリックのいずれからも、引き続き「今後のバージョンで対応します」のメッセージを表示する。

## 6. 仕様未定義(0.1-3)

1. 使用中の型のパラメータ種別の変更不可は、モデルの型管理では使用数で判定し、設定の型テーブル(雛形)では常に変更可とした。
2. 共有リソースのダイアログで採番した ID の扱い(コマンド適用時に `nextId` を引き上げる)。
3. 列のドラッグで、ドラッグ元が親の鍵(主キー、またはユニーク制約の列。共通列を含む)でないときは、リレーションシップを作らず、ステータスバーにメッセージを出す。
