## 実施した内容

- **ポストファイルの役割(role)**: メタ情報に `role=export|import` を追加(省略は export)。ポストの一覧は、エクスポート用とインポート用に分けた。エクスポート用だけが、対象DBの候補・生成・起動時の「使えるポストなし」の判定に使われる(9.6-4、9.10-5)。
- **共通ヘルパ** `post/pero.lib.js`(名前空間 `pero`): 同じフォルダにあれば、アプリがポストファイルの前に読み込む。エクスポート用(`dialect`、`Output`、`defaultSql`)、インポート用(`splitSql`、`splitTop`、`parenBody`、`ident`、`identParts`、`sqlString`、`ImportResult`)(9.12-1)。
- **ひな形** `post/template/export.post`、`post/template/import.post`(そのまま動く。テストで確認)(9.12-5)。
- **ドキュメント** `doc/contents/ポストファイルの書き方.md`(契約、メタ情報、ヘルパの一覧、エクスポート用・インポート用の書き方、デバッグ、よくある失敗)。使い方、README も更新(9.12-6)。
- **SQLインポート**(9.11、付録E): ファイル > SQLインポート。ダイアログで、インポート用ポストファイル(データベース)、SQLファイル(複数、順序変更)、取込先(新しいモデル / 現在のモデルに追加)を選ぶ。
  - 解析はインポート用ポストファイル `post/postgresql.import.post`(JavaScript)、モデルへの変換はアプリ(`lib/importer`)。追加は `ImportSqlCommand`(1コマンド、Undo可、キャッシュの再生に対応)。
  - テーブル、列、型、デフォルト、主キー、ユニーク、インデックス、CHECK、外部キー、関数、トリガー、ビュー、型、コメントを取り込む。
  - コマンドではない SELECT(FROM句あり)は SQLビュー `import_XX`。INSERT / UPDATE ほか対象外の文は「解析できないもの」。
  - 解析できないものは、ログ(warn=概要、debug=全文)に残し、結果ダイアログから別ファイルへ保存できる。
  - 実行中はオーバーレイ(「SQLを取り込んでいます…」)。新しいモデルは未保存の無題として開く。
  - 設定: インポートの実行タイムアウト(既定120秒、1〜900秒)。
  - 実データ(生産管理システムのDDL、約1.3MB)で、テーブル263、リレーションシップ791、トリガー616、関数411が、解析2秒(QuickJS)で取り込める。
- **タブの移動**(3.2-5): タブが画面に収まらないとき、両端に ◀ ▶ ボタン(1回240px。端で無効)。表示するダイアグラムが変わったとき、そのタブが見える位置へスクロール(画面外のタブは遅延構築なので、位置を見積もって近づける)。
- 仕様書(CLAUDE.md)へ統合した(0.2、1-15、3.2-5、4.1-27、9.6-4、9.10-5、9.11、9.12、10.2、11.7-11、付録D 47〜56、付録E)。

## 仮定(付録D 47〜56)

- `role` の既定は `export`。共通ヘルパは `pero.lib.js`(ポストフォルダ直下)。ひな形は `post\template`。
- 型は PostgreSQL 互換の型名を解釈(他DBは `typeId` を直接指定可)。インポートのタイムアウトは既定120秒。
- FROM句のない SELECT はコマンドとみなす。同名は取り込まない(上書き・改名しない)。`import_XX` は2桁ゼロ埋め。
- ◀▶は収まらないときだけ表示、1回240px。新しいモデルへのインポートはキャッシュの復旧の対象外。

## 仕様未定義

- インポートで取り込んだ主キー制約名は、モデルに保持しない(主キーの制約名は設定のプリフィクス/サフィックスで決まる。6.4-1)。
- 結果ダイアログの「取り込めなかった文」の保存先の拡張子は `.sql` 固定(INSERT などを含むため)。
- インポートの取込先が「追加」で、取り込みが 0 件のときは、エラー(「取り込めるものがありませんでした」)にして、モデルを変更しない。
- MySQL / SQL Server / SQLite 用のインポート用ポストファイルは同梱しない(0.3-8 と同じ方針。ひな形とガイドで作れる)。
