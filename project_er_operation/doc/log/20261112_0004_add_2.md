# 生成結果レポート 20261112_0004 追加変更 2(段階3: file_picker のバージョン変更)

指示: `issue/20261112_0004.md` の3「`file_picker` のバージョン変更」。ブランチ `feature/20261112-0004`。

## 1. 実施した内容

- `file_picker` を **8.3.7 から 13.3.3** に更新した(0003 のレポートで「13.x への移行は保存フローの見直しが必要」としていた課題)。
  - `ffi 2.x`、`win32 6.4.0` になった。Windows の実装は `windows_file_picker 2.0.2`(COMの `IFileDialog`)。
  - 以前は取得のたびに出ていた「default plugin」の警告(古い `file_picker 4.6.1` に由来)は、すでに出なくなっている。
- API の変更に、`FileDialogs`(`lib/actions/file_dialogs.dart`)だけで対応した(段階1で、ダイアログの呼び出しをここに集約してあった)。

| 操作 | 8.x | 13.x |
|---|---|---|
| ファイルを開く | `FilePicker.platform.pickFiles` | `FilePicker.pickFile`(静的メソッド) |
| フォルダを選ぶ | `FilePicker.platform.getDirectoryPath` | `FilePicker.getDirectoryPath` |
| 保存 | `saveFile` が**パスを返し**、アプリが書き込む(一時ファイル経由で原子的に) | `FilePicker.saveFile` が**バイト列を受け取り、選択と同時に書き込む**(戻り値は `Uri`) |

### 保存フローの見直し(段階1の準備を使用)

- 「ファイルに保存」(`.pero`)、JSON出力、PNG(1枚)、PDF は、保存するデータを**先に作ってダイアログへ渡す**。
- `.pero` は、`PeroFile.prepare`(整合性確認と修復を済ませたバイト列)を渡し、保存に成功したら `EditorSession` が未保存の解除、キャッシュの基点の更新、最近使ったファイルの記録を行う。
- 上書き保存(Ctrl+S)は、パスが決まっているため従来どおり**一時ファイル経由で原子的に**書き込む(変更なし)。
- 既存のファイルを選んだときの上書きの確認は、OSの保存ダイアログが行う。拡張子は、既定のファイル名の拡張子が、ダイアログの既定の拡張子として補われる。

## 3. 仕様との差異・注意

- **4.1-3「途中で失敗しても元のファイルを壊さない」**: 13.x の保存ダイアログは、選ばれたパスへ直接書き込む(アプリが一時ファイル経由にできない)。このため、**既存のファイルを選んで上書きする「ファイルに保存」では、書込みの途中で失敗すると、そのファイルが壊れる可能性がある**(新しいファイルへの保存では問題ない)。
  - 緩和策: 書き込むバイト列は、先に整合性確認を済ませている。上書き保存(Ctrl+S)は原子的に書き込む。
  - 完全な対策には、(a) 保存先の選択だけを行い書込みはしない別のパッケージ(例: `file_selector`)を使う、または (b) 8.x に戻す、のいずれかが必要。仕様どおりの動作を優先する場合は、(a) への切替を推奨する(`FileDialogs` の差し替えだけで済む)。判断を仰ぎたい。
- 8.x では、拡張子の無い入力に対し、アプリが `.pero` を補っていた。13.x では、ダイアログの既定の拡張子に任せる。

## 4. 付録D以外で新たに仮定を置いた事項

1. 保存ダイアログの書込みエラー(不正なファイル名など)は、`FileSystemException` に変換して、既存のエラーダイアログに表示する。
2. PDF/PNG/JSON のファイル名の既定値は、拡張子つきで渡す(`{名前}.pdf` など)。

## 5. 仕様未定義(0.1-3)

1. 13.x で保存の原子性が失われる場合の扱い → 「3.」のとおり、利用者の判断を仰ぐ。

## 6. 既知の課題
