## 1. 単一インスタンス化(2-14)

### 実装

- `lib/app/single_instance.dart`(Flutterに依存しない)。
  - 先に起動した側が、`%LOCALAPPDATA%\PERO\instance.lock` に**排他ロック**を取る。ロックはOSが管理するため、異常終了しても残らず、「古いロックの判定」が不要。
  - 先に起動した側は**ループバック(127.0.0.1)のみ**で待ち受け、ポート番号と**合言葉(ランダム)**を `instance.port` に書く。
  - 2つ目は `instance.port` を読んで接続し、合言葉と引数(JSON1行)を送る。受理の応答(`OK`)を受け取ったら終了する(終了コード0)。
  - 合言葉が違う接続、JSONでない入力は無視する。
- 起動処理(`lib/app/pero_app.dart`): Flutterの初期化の直後(ウィンドウを作る前)に確認する。渡せたときは `exit(0)`。
- 既存のウィンドウ(`MainScreen`): 引数を受け取ると、最小化なら元に戻し、前面に出してフォーカスを移す。`.pero` が指定されていれば、未保存確認の後に開く。
- 正常終了時にポート情報を消し、ロックを解放する。
- **開発用の抜け道**: 環境変数 `PERO_ALLOW_MULTIPLE=1` で多重起動を許す(デバッグの並行起動用)。
- 渡せなかった場合(既存のインスタンスが応答しない)は、起動できなくなることを避けるため単独で起動する。
- **`.pero` の関連付け**: `tools/register_file_association.ps1`(現在のユーザーのみ、HKCU。`-Unregister` で解除)。**このスクリプトは、レジストリを書き換えるため、こちらでは実行していない**(構文の確認のみ)。

### 検証

- 単体テスト6件(`test/app/single_instance_test.dart`): 引数の受け渡し、繰り返し、引数なし、終了後の再起動、古いポート情報、合言葉違い・不正入力の拒否。
- **実際の exe を2つ起動して確認**: 2つ目は約1.8秒で終了(終了コード0)し、既存のウィンドウのタイトルが `sample.pero` から `second.pero` に変わった。起動中のプロセスは1つのまま。×ボタン相当の終了で、ポート情報(`instance.port`)が消えた。

## 2. 性能計測(2-8)

目標: テーブル200、列の合計3000、リレーションシップ300で、パン・ズーム・ドラッグが目安30fps以上(1フレーム33ms以下)。

### 方法

`test/performance/large_model_test.dart`。テーブル200(各15列、合計3000列)、リレーションシップ約300のモデルを作り、`flutter test` の中で計測した(中央値、`Stopwatch`)。テストの上限は、環境差を見込んで目標の数倍に緩めてある。

### 結果(このマシン。Windows、`flutter test`)

| 計測 | 結果 | 目標(33ms)に対して |
|---|---|---|
| 描画1フレーム: 100%(表示領域のみ) | 約6ms | 余裕あり |
| 描画1フレーム: 100%・20個選択 | 約5ms | 余裕あり |
| 描画1フレーム: 25%(全体が見える) | 約16ms | 余裕あり |
| 描画: 文字レイアウトのキャッシュが空の最初のフレーム(50%) | 約10ms(最大13ms) | 余裕あり |
| 描画: 実フォント(MS Gothic)、50%のコールド / ウォーム | 約14ms / 約6ms | 余裕あり |
| 描画: 実フォント、25%全体のコールド | 約22ms | 余裕あり |
| ドラッグ中の1ポインタ移動あたり(ウィジェットの再構築。build+layout+paint) | 約7ms(最大15ms) | 余裕あり |
| 全エンティティの寸法計算 | 約1.3ms | — |
| リレーションシップの線分の計算(300本) | 約4.5ms | — |
| ドラッグの確定(`MovePlacementsCommand`、10個) | 約24ms | 1回の操作のため問題なし |
| `.pero`(約1.3MB)の書出し / 読込+整合性確認 | 約13ms / 約13ms | — |
| 生成前検証 / 生成用JSON | 約7ms / 約13ms | — |

### 結論

- **目標を満たしている**(最も重い計測でも1フレーム22ms以下)。**最適化は行っていない**。
- 描画は、表示領域外のエンティティを省略すること、文字のレイアウト結果を再利用すること(`TextCache`)で、規模にほとんど依存しない。
- **限界**: 計測できたのは、描画命令の記録(CPU側)とウィジェットの再構築まで。**GPUでのラスタライズ(実際の画面への描画)の時間と、実アプリでの体感のfpsは測っていない**。実アプリでの確認(`flutter run --profile` とパフォーマンスオーバーレイ)は、画面を人が見て行う必要があるため、今回は行っていない。
- ドラッグ確定のコマンドが約24msなのは、コマンドの前後でモデル全体の状態を比較して差分(Undo用)を作るため(列3000でおよそ1回24ms)。操作1回あたりなので問題はないが、モデルがさらに大きくなると比例して増える。

## 4. 付録D以外で新たに仮定を置いた事項

1. 単一インスタンスの判定は、ユーザーごと(`%LOCALAPPDATA%\PERO`)。別のユーザーのセッションの起動は、別のインスタンスとして扱う。
2. 「ウィンドウを前面に出す」は、最小化の解除、表示、フォーカスで実現した(Windowsの前面化の制約により、フォーカスが奪えず、タスクバーの点滅になる場合がある)。
3. 引数に `.pero` 以外が渡されたときは、前面に出すだけで何も開かない。
