# PERO 使い方(v0.1.0)

ER図を作成・編集し、SQLを生成する Windows 用アプリです。

## 起動

- `project_er_operation.exe` を実行します。`.pero` ファイルをコマンドライン引数で渡すと、起動時にそのファイルを開きます。
- 実行ファイルと同じフォルダに `post\postgresql.post`(同梱のポストファイル)があります。

## 画面

| 領域 | 内容 |
|---|---|
| メニューバー | ファイル / 操作 / RUN |
| 左(160px) | サイドメニュー。「テーブル」をキャンバスへドラッグ&ドロップで追加 |
| 中央 | ダイアグラムのタブ(「+」で追加、ダブルクリックで名前変更、ドラッグで並べ替え、「×」で削除)とキャンバス |
| 右上 | プロパティ。機能別のタブに分かれています(何も選択していなければ「モデル」「ダイアグラム」、テーブルは「基本」「列」「制約」「トリガー」「クエリ」、ビューは「基本」「定義」「クエリ」、リレーションシップは「基本」「列対応」「参照規則」)。入力欄は1項目1行で、列は見出しをクリックすると項目が開きます。同じ種類を選んでいる間はタブを保持します |
| 右下 | テーブルリスト(検索、クリックで選択、未配置は灰色。ダブルクリックで配置) |
| 最下部 | 通知メッセージ、選択数、ズーム率(クリックで100%) |

## キャンバスの操作

| 操作 | 方法 |
|---|---|
| 選択 | クリック。Shift/Ctrlで追加・解除。空白のドラッグで矩形選択。Ctrl+Aで全選択。Escで解除 |
| 移動 | **ヘッダ**をドラッグ(10pxグリッドにスナップ。Alt押下中は解除)。ドラッグ中は、動かしているエンティティが半透明になり、ドラッグ元には何も表示されません(ドロップで確定)。ロック中のものは動かない |
| リレーションシップの作成 | テーブルの**列行**を別のテーブル(またはその列行)へドラッグ&ドロップ。ドラッグした列が親、ドロップ先が子。ドロップ先が列ならその列が外部キー列になる |
| パン | 中ボタンのドラッグ、または Space+ドラッグ。ホイールで縦、Shift+ホイールで横 |
| ズーム | Ctrl+ホイール(25〜400%)。Ctrl+0で100% |
| 折りたたみ | ヘッダ右端の ▼/▶ |
| プロパティ編集へ | テーブルをダブルクリック(論理名にフォーカス) |
| 右クリック | 場所に応じたメニュー(追加、削除、コピー、ロック、表示するダイアグラムなど) |

用紙ページ(破線)は、エンティティをドロップしたときに、はみ出した方向へ自動で増減します。

## テーブルとリレーションシップ

1. テーブルを追加すると、列「ID」(auto、PK)を1つ持ちます。プロパティで論理名・物理名・列などを編集します。
2. テーブルを2つ選択して **操作 > リレーションシップの追加** を実行します。IDの小さい方が親になります。子の外部キー列は、親の鍵と同名(次に部分一致)の列を使い、無ければ子に作成します。
3. リレーションシップのプロパティで、依存関係(識別関係)、多重度、ON DELETE / ON UPDATE などを変更できます。依存関係の変更などで子の外部キー列のPK/NotNullを連動させるときは確認ダイアログが出ます。
4. 親と子を入れ替えるには、プロパティの入替ボタンを使います。

入力は Enter またはフォーカスを外すと確定し、1回の確定が1回の Undo になります。不正な値は赤枠で示され、確定されません。

## 保存と復旧

- 保存形式は `.pero`(JSON)。ファイルを開く/保存するときに整合性確認を行い、修復した場合は内容を表示します(開くときは元のファイルを `.pero.bak` に退避)。
- 保存済みのファイルの編集内容は `%LOCALAPPDATA%\PERO\cache\` に差分で記録され、異常終了後の起動時に復元を提案します。
- 設定のバックアップを有効にしていると、一定間隔で `%LOCALAPPDATA%\PERO\backup\` に保存します。
- ログは `%LOCALAPPDATA%\PERO\logs\pero_yyyyMMdd.log` です。

## SQLの生成

1. **RUN > 生成実行(F5)**。モデルのプロパティで「ポストファイルのパス」を指定します(空のときはファイルを選択するダイアログが開きます)。
2. 生成前検証でエラーがあると一覧が表示され、生成は行われません。警告は生成後の結果に表示されます。
3. 出力先は `{出力フォルダ}\{出力ファイル名}.sql`。出力フォルダが空なら `.pero` と同じフォルダ(未保存ならドキュメント)です。
4. **RUN > JSON出力** は、ポストファイルに渡す生成用JSONをそのまま書き出します。
5. **RUN > 画像出力** は現在のダイアグラムをPNGに出力します(PDFは今後対応)。

### ポストファイルを書く

- 拡張子 `.post`、JavaScript(ES2020)。先頭10行以内に次の形式のメタ情報が必須です。

  ```js
  // @post name=PostgreSQL targetDb=postgresql apiVersion=1
  ```

- `function main(jsonText)` が生成用JSON(CLAUDE.md の付録B)を受け取り、ファイル全文(文字列)を返します。エラーは `throw` します。
- ファイル・ネットワーク・タイマーは使えません。`console.log` はログに記録されます。
- 同梱の `post\postgresql.post` を参考にしてください。トリガーの本体は、トリガー関数を定義するSQLを書きます(入力の場合の関数名は `{{trigger}}`)。

## 共有リソースの管理(操作メニュー)

| メニュー | 内容 |
|---|---|
| メソッド管理 | ファンクション/トリガーの登録。名前、外部定義、対象DBごとの呼出し式と本体。削除すると、参照(列のデフォルト、トリガー)は解除されます。関数ビューが参照しているメソッドは削除できません |
| 共通列パターン管理 | テーブル物理名の正規表現で、共通列を自動付与します。正規表現の試験欄と、一致するテーブルの一覧があります |
| 型管理 | 型の追加・編集・削除。標準型は物理名テンプレートだけ編集でき、「初期値に戻す」があります。使用中の型の削除は置換先を選びます。設定の「型」は新規モデルの雛形です |

## 関数ビューとトリガー

- **操作 > ビューの追加(関数ビュー)**(またはサイドメニューからドロップ)で、メソッド・引数・戻り列を指定します。プロパティの「定義を編集」でも開きます。
- テーブルのプロパティの「トリガー」で、追加・削除・ドラッグによる順の変更、本体の元(パブリック/入力)、タイミング、イベント、WHEN を編集します。

## 未対応の機能

結合ビューの定義ダイアログ(.peroからの読込は可能)、PDF出力、単一インスタンス化。詳細は `doc/log/` のレポートを参照してください。
