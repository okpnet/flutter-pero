# PERO 使い方(v0.3.0)

ER図を作成・編集し、SQLを生成する Windows 用アプリです。

## 起動

- `project_er_operation.exe` を実行します。**多重起動はできません**。2つ目を起動すると、ファイルパスを既存のウィンドウに渡して終了し、既存のウィンドウが前面に出ます(`.pero` が指定されていれば、未保存確認の後に開きます)。`.pero` ファイルをコマンドライン引数で渡すと、起動時にそのファイルを開きます。
- 実行ファイルと同じフォルダに `post\postgresql.post`(同梱のポストファイル)があります。

## 画面

| 領域 | 内容 |
|---|---|
| 上(中央) | 検索ボックス(正規表現、範囲) |
| 左(200px) | サイドメニュー(項目は折り返さず1行)。タブ「追加」(テーブルなどをキャンバスへドラッグ&ドロップで追加)、「ファイル」「操作」「RUN」(従来のメニュー) |
| 中央 | ダイアグラムのタブ(「+」で追加、ダブルクリックで名前変更、ドラッグで並べ替え、「×」で削除)とキャンバス |
| 右上 | プロパティ。機能別のタブに分かれています(何も選択していなければ「モデル」「ダイアグラム」、テーブルは「基本」「列」「制約」「トリガー」「クエリ」、ビューは「基本」「定義」「クエリ」、リレーションシップは「基本」「列対応」「参照規則」)。入力欄は1項目1行で、列は見出しをクリックすると項目が開きます。同じ種類を選んでいる間はタブを保持します |
| 右下 | テーブルリスト(検索、クリックで選択、未配置は灰色。ダブルクリックで配置) |
| 最下部 | 通知メッセージ、選択数、ズーム率(クリックで100%) |

ファイルを開いている間は、画面全体が暗くなり、くるくる(ローディング)とファイル名が表示されます。終わるまで操作はできません。

キャンバスを広く使いたいときは、タブバーの左端のボタン(サイドメニュー)と右端のボタン(プロパティとテーブルリスト)で、それぞれ折りたたみ/スライドインできます。開閉の状態は次回の起動でも保たれます。

## テーマ(色)

設定 > 表示 > 色テーマで、システムテーマ(OSの設定に従う)/ ダークテーマ / ライトテーマ / ユーザーテーマを選べます。ユーザーテーマは、「ユーザーテーマのファイル」に、theme_lib のテーマJSONを指定します(ライト/ダークの両方を書けます)。読み込めないときはシステムテーマで表示し、ステータスバーに理由を表示します。

```json
{
  "schemaVersion": 1,
  "id": "sunset",
  "name": "Sunset",
  "light": { "seedColor": "#E65100" },
  "dark": { "seedColor": "#FF8A65" }
}
```

## ポストファイルと対象のデータベース

- ポストフォルダにあるポストファイルのメタ情報(`targetDb`)から、どのデータベースに適用するかが決まります。モデルのプロパティの「ポストファイル」で一覧から選ぶと、対象のデータベースも決まります。
- 画面には、ポストファイルがある種類(postgresql / mysql / sqlserver / sqlite)だけが表示されます(対象のデータベースの候補、メソッド・型・トリガーの対象DBごとのタブ)。入力済みの値は消えません。
- 自分で作ったポストファイルの `targetDb` が上の4種類でないときは、設定 > ポストファイル > 「種類(kind)の関連付け」に `ファイル名=種類` をカンマ区切りで指定します(例: `mariadb.post=mysql`)。
- 生成実行(F5)の間、指定したポストファイルはロックされ、編集・削除・名前の変更はできません(生成が終われば解除されます)。ポストファイルが存在しないときは、エラーを表示して生成を止めます。ポストファイルの種類がモデルの対象のデータベースと違うときは、対象のデータベースをポストファイルの種類に変更して生成します(Undoできます)。

## 検索
画面上部中央の検索ボックスに入力すると、一致するオブジェクトがキャンバス上でハイライトされます。右の「.*」で正規表現、プルダウンで範囲(全て / テーブル / ビュー / 列 / 関数 / トリガー / コメント)を切り替えます。親(テーブル、ビュー)は薄く、子(列行、関数の定義、トリガーの中のメソッド)は濃く表示します。
検索ボックスの右の「↑」「↓」(または Enter / Shift+Enter)で、ヒットしたオブジェクトへ順に移動します(最後の次は先頭へ循環。別のダイアグラムに配置されていれば、そのタブへ切り替わります)。

## キャンバスの操作

| 操作 | 方法 |
|---|---|
| 選択 | クリック。Shift/Ctrlで追加・解除。空白のドラッグで矩形選択。Ctrl+Aで全選択。Escで解除 |
| 移動 | **ヘッダ**をドラッグ(10pxグリッドにスナップ。Alt押下中は解除)。ドラッグ中は、動かしているエンティティが半透明になり、ドラッグ元には何も表示されません(ドロップで確定)。ロック中のものは動かない |
| リレーションシップの作成 | テーブルの**列行**を別のテーブル(またはその列行)へドラッグ&ドロップ。ドラッグした列が親、ドロップ先が子。ドロップ先が列ならその列が外部キー列になる。ドラッグ中に別のダイアグラムのタブの上へ約0.6秒置くとそのダイアグラムへ切り替わり、そちらのテーブルへもドロップできる |
| パン | 中ボタンのドラッグ、または Space+ドラッグ。ホイールで縦、Shift+ホイールで横 |
| ズーム | Ctrl+ホイール(25〜400%)。Ctrl+0で100% |
| 折りたたみ | ヘッダ右端の ▼/▶ |
| プロパティ編集へ | テーブルをダブルクリック(論理名にフォーカス) |
| 右クリック | 場所に応じたメニュー(追加、削除、コピー、ロック、表示するダイアグラムなど) |

用紙ページ(破線)は、エンティティをドロップしたときに、はみ出した方向へ自動で増減します。

## テーブルとリレーションシップ

1. テーブルを追加すると、列「ID」(auto、PK)を1つ持ちます。プロパティで論理名・物理名・列などを編集します。
2. テーブルを2つ選択して **操作 > リレーションシップの追加** を実行します。IDの小さい方が親になります。子の外部キー列は、親の鍵と同名(次に部分一致)の列を使い、無ければ子に作成します。
3. リレーションシップのプロパティで、依存関係(識別関係)、多重度、ON DELETE / ON UPDATE などを変更できます。依存関係の変更などで子の外部キー列のPK/NotNullを連動させるときは確認ダイアログが出ます。
4. 親と子を入れ替えるには、プロパティの入替ボタンを使います。
5. **自己参照**(親と子が同じテーブル)も作れます。テーブルを1つだけ選んで **リレーションシップの追加** を実行するか、主キーの列行を同じテーブルの別の列行へドラッグします。依存関係は無効で作られ、テーブルの右辺から出て戻る折れ線で描かれます。
6. 「参照規則」タブの **遅延可否** で、`DEFERRABLE INITIALLY DEFERRED` などを指定できます。

入力は Enter またはフォーカスを外すと確定し、1回の確定が1回の Undo になります。不正な値は赤枠で示され、確定されません。

## 保存と復旧

- 保存形式は `.pero`(JSON)。ファイルを開く/保存するときに整合性確認を行い、修復した場合は内容を表示します(開くときは元のファイルを `.pero.bak` に退避)。
- 保存済みのファイルの編集内容は `%LOCALAPPDATA%\PERO\cache\` に差分で記録され、異常終了後の起動時に復元を提案します。
- 設定のバックアップを有効にしていると、一定間隔で `%LOCALAPPDATA%\PERO\backup\` に保存します。
- ログは `%LOCALAPPDATA%\PERO\logs\pero_yyyyMMdd.log` です。

## SQLの生成

1. **RUN > 生成実行(F5)**。モデルのプロパティの「ポストファイル」(空のときは、ポストフォルダから対象のデータベースのものが選ばれます)でSQLを生成します。
2. 生成前検証でエラーがあると一覧が表示され、生成は行われません。警告は生成後の結果に表示されます。
3. 生成できたら、**ファイルの保存ダイアログ**で保存先を選びます。拡張子は `sql` です(設定で変えられますが、ポストファイルと同じ `post` は使えません)。既定のフォルダとファイル名は `{出力フォルダ}{出力ファイル名}.sql`(出力フォルダが空なら `.pero` と同じフォルダ、未保存ならドキュメント)です。まだ存在しないファイルも指定できます。キャンセルすると、ファイルは書かれません。 生成の間(ボタンを押してから保存ダイアログが閉じるまで)は、画面が暗くなり、くるくる(ローディング)と「生成しています…」が表示されて操作できません(F5の連打や2回目のクリックも防ぎます)。
4. **RUN > JSON出力** は、ポストファイルに渡す生成用JSONをそのまま書き出します。
5. **RUN > 画像出力** は現在のダイアグラムを PNG または PDF に出力します。範囲は「用紙ページごと」(PNG は1ページ=1ファイル、PDF は1ページ=PDFの1ページ)か「全体を1枚」で、解像度(dpi 100〜600)を指定します。PDFのページの大きさは用紙サイズです。

### ポストファイルを書く

- 拡張子 `.post`、JavaScript(ES2020)。先頭10行以内に次の形式のメタ情報が必須です。

  ```js
  // @post name=PostgreSQL targetDb=postgresql apiVersion=3
  ```

- `function main(jsonText)` が生成用JSON(CLAUDE.md の付録B)を受け取り、ファイル全文(文字列)を返します。エラーは `throw` します。
- ファイル・ネットワーク・タイマーは使えません。`console.log` はログに記録されます。
- 同梱の `post\postgresql.post` を参考にしてください。トリガーの本体は、トリガー関数を定義するSQLを書きます(入力の場合の関数名は `{{trigger}}`)。

## 共有リソースの管理(操作メニュー)

| メニュー | 内容 |
|---|---|
| メソッド管理 | ファンクション/トリガーの登録。名前、外部定義、対象DBごとの呼出し式と本体。削除すると、参照(列のデフォルト、トリガー)は解除されます。関数ビューが参照しているメソッドは削除できません |
| 共通列パターン管理 | テーブル物理名の正規表現で、共通列を自動付与します。正規表現の試験欄と、一致するテーブルの一覧があります |
| 型管理 | 複合型・列挙型(ユーザー定義型)も追加できます。型の追加・編集・削除。標準型は物理名テンプレートだけ編集でき、「初期値に戻す」があります。使用中の型の削除は置換先を選びます。設定の「型」は新規モデルの雛形です |

## 関数ビューとトリガー

- **操作 > ビューの追加(結合ビュー)** で、ソースのテーブル(最初が FROM)、結合種別(INNER/LEFT/RIGHT/FULL)、結合条件、出力列(別名・論理名)、WHERE を指定します。ソースを追加すると、既存のリレーションシップから結合条件の初期値が提案されます(編集できます)。プロパティの「定義を編集」でも開きます。
- **操作 > ビューの追加(関数ビュー)**(またはサイドメニューからドロップ)で、メソッド・引数・戻り列を指定します。プロパティの「定義を編集」でも開きます。
- テーブルのプロパティの「トリガー」で、追加・削除・ドラッグによる順の変更、本体の元(パブリック/入力)、タイミング、イベント、WHEN を編集します。

## スキーマ・DROP・主キー制約名

- モデルのプロパティの「出力にスキーマを含める」を有効にし、「スキーマ」を入力すると、テーブル名・ビュー名を `スキーマ.名前` で出力します。ダイアグラムのプロパティにもスキーマがあり、空でなければ、そのダイアグラムに配置したエンティティに使われます(複数のダイアグラムに配置しているときは、タブ順で最初のダイアグラムのスキーマ)。
- 設定 > 生成 の「再実行用のDROP文を付ける」を有効にすると、ユーザー定義型・テーブル(`CASCADE`)・ビューの前に `DROP ... IF EXISTS` を出力します。
- 設定 > 生成 の「主キー制約名のプリフィクス/サフィックス」で、主キー制約名(既定 `{テーブル}_pk`)を変えられます。

## SQLビュー・CHECK制約など

- **操作 > ビューの追加(SQLビュー)**(またはサイドメニュー)で、SELECT文をそのまま持つビューを作れます。キャンバスに表示する列は任意で入力します。
- テーブルのプロパティの「制約」で、CHECK制約と、ユニークの NULLS NOT DISTINCT を指定できます。列のデフォルトには「式」(例 `CURRENT_DATE + 30`)を選べます。空文字のデフォルトは、標準メソッド `empty_string` を選びます。
- トリガーには関数への引数と、UPDATEの対象(テーブル全体 / 指定した列)を設定できます。
- メソッドには、コメント、引数の定義、依存テーブル・ビュー(その後にファンクションを出力)を設定できます。

- ユーザー定義型(複合型・列挙型)には、コメントとスキーマを付けられます。長さを指定しない `varchar` は、標準型「varchar(長さなし)」を使います。型・メソッドのスキーマは、モデルの「出力にスキーマを含める」が有効のとき、`CREATE TYPE`、トリガーの呼出し、`COMMENT ON` に付きます。
- 生成するSQLの改行コードは設定(CRLF / LF)に従いますが、引用符(`'...'`)の中の改行は変換しません(コメントなどの内容を変えないため)。

## SQLファイルの取り込み

`dart run tool/sql_to_pero.dart <出力.pero> <結果メモ.txt> <SQLファイル>...` で、PostgreSQLのDDLから `.pero` を作れます(`doc/sample/pms_test.pero` は例)。取り込めなかった要素は、モデルの終了クエリにコメントとして残ります。

## .pero の関連付け

`tools/register_file_association.ps1 -ExePath <project_er_operation.exe のパス>` を実行すると、現在のユーザーについて `.pero` を PERO に関連付けます(管理者権限は不要)。`-Unregister` で解除します。関連付け後は、`.pero` をダブルクリックすると PERO で開き、すでに起動していれば既存のウィンドウで開きます。
