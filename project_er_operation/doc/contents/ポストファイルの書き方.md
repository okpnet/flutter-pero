# ポストファイルの書き方

PERO は、SQL を作る(エクスポート)ときも、SQL を読む(インポート)ときも、**ポストファイル**(JavaScript)に処理を任せます。
データベースごとの違いは、ポストファイルが吸収します。このガイドは、自分のデータベース用のポストファイルを作るための手引きです。

## 1. 最短の手順

1. ひな形をコピーします。
   - エクスポート用: `post\template\export.post`
   - インポート用: `post\template\import.post`
2. コピーしたファイルを、`post` フォルダ(実行ファイルと同じフォルダ内。設定で変更可)へ置き、名前を変えます(例: `mydb.post`)。
3. 1行目のメタ情報(`name`、`targetDb`)を書き換えます。
4. 中身を、対象のデータベースに合わせて直します。
5. PERO を起動(または設定を適用)すると、ポストファイルが一覧に出ます。

ひな形は、そのまま動きます。まず動かしてから、少しずつ直すのが近道です。

## 2. 契約(守ること)

| 項目 | 内容 |
|---|---|
| 言語 | JavaScript(ES2020)。UTF-8。QuickJS で実行します |
| 入口 | `function main(jsonText)`。引数は JSON 文字列、戻り値は**文字列** |
| エラー | `throw new Error('…')`。処理を止め、メッセージを画面に出します |
| 使えないもの | ファイル、ネットワーク、タイマー(`setTimeout` など) |
| ログ | `console.log(…)` は、ログ(info)に記録されます |
| メタ情報 | 先頭10行以内に必ず書きます(次の節) |

### メタ情報

```js
// @post name=私のデータベース targetDb=postgresql apiVersion=3 role=export
```

| キー | 意味 |
|---|---|
| `name` | 一覧に出す表示名(空白を含めてよい) |
| `targetDb` | `postgresql` / `mysql` / `sqlserver` / `sqlite`。これ以外の値は、設定 > ポストファイル > 種類(kind)の関連付けで、既存の種類へ対応づけます |
| `apiVersion` | 現在は `3`。アプリと合わないポストファイルは、一覧に出ません |
| `role` | `export`(SQL を作る。省略時)または `import`(SQL を読む) |

`role` で一覧が分かれます。`export` は、対象のデータベースの候補や生成実行(F5)で使われ、`import` は「SQLインポート」のダイアログで使われます。

## 3. 共通ヘルパ `pero.lib.js`

`post` フォルダに `pero.lib.js` があると、アプリがポストファイルの前に読み込みます。ポストファイルからは `pero.xxx` として使えます。
ヘルパを使わなくても、ポストファイルは書けます(同梱の `postgresql.post` などは使っていません)。

### 共通

| 関数 | 説明 |
|---|---|
| `pero.stripTrailing(s)` | 末尾の空白を除く |
| `pero.endSemi(s)` | 末尾に `;` が無ければ付ける |

### エクスポート用

| 関数 | 説明 |
|---|---|
| `pero.dialect(opts)` | 方言を作る。`opts.reserved`(引用が必要な予約語。小文字)、`opts.quote(name)`(識別子の引用)、`opts.literal(s)`(文字列リテラル)。戻り値 `d` は `d.q(name)`(識別子)、`d.qt(schema, name)`(スキーマ付き)、`d.list(names)`(`a, b`)、`d.lit(s)`(文字列リテラル) |
| `pero.Output()` | 出力の組立。`push(文)` した文を空行で区切る。空の文は無視する。`toString()` で全文(末尾に改行) |
| `pero.defaultSql(column, d)` | 列のデフォルトを SQL の式にする。デフォルトなしは `null` |

### インポート用

| 関数 | 説明 |
|---|---|
| `pero.splitSql(text, opts)` | SQL を文に分ける。引用符、ドル引用符、コメントの中の `;` では分けない。戻り値は `{ raw, clean, line }` の配列(`raw`=コメント付きの文、`clean`=コメントを除いた文、`line`=開始行)。`opts.backslashEscapes` を真にすると、文字列中の `\` をエスケープとして扱う(MySQL など) |
| `pero.splitTop(s)` | 最上位のカンマで分ける(括弧と引用符の中は分けない) |
| `pero.parenBody(s, from)` | `from` 以降の最初の `(` に対応する `)` までの内側(`{ body, end }`)。なければ `null` |
| `pero.identParts(raw)` / `pero.ident(raw)` | `s.t.c` のような修飾名を分ける / 最後の要素を返す。引用符なしは小文字にする |
| `pero.sqlString(s)` | `'…'` や `E'…'` を値にする。リテラルでなければ `null` |
| `pero.ImportResult(dialect)` | インポート結果の組立(`add`、`unparsed`、`nextViewName`、`toJson`) |

## 4. エクスポート用ポストファイル(`role=export`)

入力は**生成用JSON**(仕様書の付録B。RUN > JSON出力で、実際の内容を見られます)。戻り値は、生成する SQL の全文です。

```js
function main(jsonText) {
  var model = JSON.parse(jsonText);
  var out = pero.Output();
  out.push(model.model.startQuery);
  model.tables.forEach(function (t) { out.push(createTable(t)); });   // 親から子の順
  model.foreignKeys.forEach(function (fk) { out.push(addForeignKey(fk)); });
  out.push(model.model.endQuery);
  return out.toString();
}
```

押さえどころ:

- `tables` は親から子の順です。循環する外部キーには `deferred: true` が付くので、すべてのテーブルを作った後で `ALTER TABLE` します。
- 列の `type` は、対象データベース用に展開済みの文字列(`varchar(255)` など)です。`typeCategory`(number / string / boolean …)で、値の引用符の要否を決めます。
- 名前はすべて物理名です。制約名は解決済みです。
- スキーマ名は `schema` などで渡されます(出力にスキーマを含める設定のときだけ入ります)。
- 出力の改行は `\n` で書きます。アプリが、設定の改行コードに変換します(引用符の中は変換しません)。
- 出力する順序(型 → 関数 → テーブル → 外部キー → ビュー → トリガー)は、仕様書 9.6-7 を参照してください。

## 5. インポート用ポストファイル(`role=import`)

入力は `{ "files": [ { "name": "a.sql", "text": "…SQL全文…" } ] }`。戻り値は**インポート結果**(仕様書 付録E)の JSON です。
解析(SQL を読むこと)だけをポストファイルが行い、モデルへの変換はアプリが行います。

```js
function main(inputText) {
  var input = JSON.parse(inputText);
  var res = pero.ImportResult('postgresql');
  input.files.forEach(function (f) {
    pero.splitSql(f.text).forEach(function (s) { statement(res, s, f.name); });
  });
  return res.toJson();
}
```

1つの文を、種類で振り分けます(`s.clean` を使うと、コメントを気にしなくて済みます)。

| 結果に追加する | 呼び出し |
|---|---|
| テーブル | `res.add('tables', { name, schema, columns: [ { name, type, notNull, default, primaryKey } ] })` |
| 制約・インデックス | `res.add('constraints', { kind: 'primaryKey' / 'unique' / 'check' / 'foreignKey' / 'index', table, … })` |
| 関数 | `res.add('functions', { name, args, returns, body })`(`body` は CREATE 文の全文) |
| ビュー | `res.add('views', { name, sql })` |
| トリガー | `res.add('triggers', { name, table, timing, events, forEach, when, function, args })` |
| 型 | `res.add('types', { name, kind: 'enum' / 'composite', values, fields })` |
| コメント | `res.add('comments', { kind: 'table' / 'column' / …, target, text })` |

### 決まりごと

- **解析できない文は、捨てずに `res.unparsed(kind, reason, s, file)` に渡します。** アプリが、ログへ記録し、別ファイルへ保存できるようにします。
- `INSERT` / `UPDATE` などのデータの操作は、解析できないものにします。
- コマンドではない `SELECT`(FROM 句があるもの)は、ビューにします。名前は `res.nextViewName()`(`import_01`、`import_02` …)。`fromSelect: true` を付けます。
- 型は、列の `type` に**型名の文字列**を入れると、アプリが PERO の標準型へ対応づけます(PostgreSQL 互換の名前を解釈)。ほかのデータベース用では、`typeId`(`integer`、`varchar` など標準型の ID)と `length` などを直接指定できます。
- 関数・トリガー関数の本体は、`ImportResult` の `dialect`(対象データベース)のタブに入ります。

### インポート用の同梱例

`post\postgresql.import.post` は、PostgreSQL の DDL(CREATE TABLE、ALTER TABLE、CREATE INDEX、CREATE FUNCTION、CREATE TRIGGER、CREATE VIEW、CREATE TYPE、COMMENT ON)を読みます。自分のデータベース用を作るときの実例として読んでください。

## 6. 作ったポストファイルを試す

1. `post` フォルダへ置きます(アプリの起動時、または設定の適用時に、一覧が更新されます)。
2. エクスポート用は、RUN > 生成実行(F5)。インポート用は、ファイル > SQLインポート。
3. うまくいかないときは、`console.log` でログへ出して確認します。ログは `%LOCALAPPDATA%\PERO\logs\` にあります。設定 > ログ > レベルを `debug` にすると、詳細が出ます。
4. エクスポート用に渡される JSON は、RUN > JSON出力で、ファイルに書き出して確認できます。

## 7. よくある失敗

| 症状 | 原因と対処 |
|---|---|
| 一覧に出ない | 1行目のメタ情報が無い、10行目より後にある、`apiVersion` が違う、`role` が `export` / `import` 以外。ファイルは `post` フォルダ**の直下**に置く(`template` の中は対象外) |
| 「…に関連付けてください」と出る | `targetDb` が `postgresql` / `mysql` / `sqlserver` / `sqlite` 以外。設定 > ポストファイル > 種類(kind)の関連付けに、`mydb.post=mysql` のように書く |
| `pero is not defined` | `pero.lib.js` が、ポストファイルと同じフォルダに無い |
| 戻り値が文字列でない | `main` が `return` していない、または `JSON.stringify` を忘れている(インポート用は `res.toJson()`) |
| タイムアウトする | 設定 > ポストファイルの実行タイムアウト(インポートは「インポートの実行タイムアウト」)を長くする。正規表現が極端に遅くなっていないか確認する |
| 文字化けする | ポストファイルは UTF-8(BOM なし)で保存する |
